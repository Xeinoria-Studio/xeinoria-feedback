## 🇫🇷 Français

Pour ne pas que les retours se dispersent à travers les ~15 dépôts de l'organisation, **toutes les remontées utilisateur arrivent ici**, quel que soit le serveur ou le plugin concerné.

### Que mettre ici

- 🐛 **Bugs** — quelque chose qui ne marche pas comme attendu (un Skript qui crash, un MOTD cassé, un téléport qui rate…).
- 💡 **Suggestions** — une feature gameplay, une amélioration UX, une idée d'évènement.
- ❓ **Questions** — vous ne trouvez pas comment faire un truc, vous voulez comprendre une mécanique.

### Que **ne pas** mettre ici

- 🔐 **Failles de sécurité / exploits** — passez par Discord en privé à un staff (ou ouvrez une [security advisory](https://github.com/Xeinoria-Studio/xeinoria-feedback/security/advisories/new) privée).
- 🛠️ **Pull requests** — les PR techniques restent sur le dépôt concerné (`xeinoria-server-survie` pour la survie, etc.), parce qu'elles modifient le code de ce dépôt-là.

### Comment ça marche

1. Cliquez sur le lien adapté en haut de page (bug / idée / question).
2. Remplissez le template — précisez le **serveur concerné** (hub, survie, créa, nwland) si pertinent.
3. Le staff lit, triage et tague. Si c'est un bug réel, on lie l'issue au dépôt technique concerné dans une PR.

### Pourquoi tout centraliser ici ?

Plus simple pour vous : **un seul endroit**, pas besoin de deviner si le souci vient du Skript, de la config Paper, du proxy ou d'un plugin tiers. Plus simple pour nous : un seul board à triager.

## 🇬🇧 English

To keep feedback from scattering across the ~15 repos in the organization, **every user-facing report lands here**, regardless of which server or plugin is involved.

### What goes here

- 🐛 **Bugs** — something not working as expected (a Skript crash, a broken MOTD, a teleport that fails…).
- 💡 **Suggestions** — a gameplay feature, a UX improvement, an event idea.
- ❓ **Questions** — you can't figure out how to do something, you want to understand a mechanic.

### What does **not** go here

- 🔐 **Security issues / exploits** — DM a staff on Discord, or open a private [security advisory](https://github.com/Xeinoria-Studio/xeinoria-feedback/security/advisories/new).
- 🛠️ **Pull requests** — code PRs stay on the relevant repo (`xeinoria-server-survie` for survival, etc.), since they edit that repo's source.

### How it works

1. Click the matching link at the top (bug / idea / question).
2. Fill the template — mention the **affected server** (hub, survival, creative, nwland) when relevant.
3. Staff reads, triages and labels. If it's a real bug, we link the issue to the technical repo in a follow-up PR.

### Why centralize here?

Easier for you: **a single place**, no need to guess whether the issue lives in a Skript, a Paper config, the proxy or a third-party plugin. Easier for us: a single board to triage.
